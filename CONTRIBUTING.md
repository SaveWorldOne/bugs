# Contributing to SaveWorldOne Bug Tracker

Thank you for your interest in contributing to the SaveWorldOne Bug Tracker! This document provides guidelines for contributing to this issue-tracking repository.

## 🎯 Purpose

This repository is dedicated to tracking bugs, issues, and feature requests. **No code is stored here** - it's purely for issue management.

## 📝 How to Contribute

### Reporting Bugs

1. **Search first**: Before creating a new bug report, search [existing issues](../../issues) to avoid duplicates
2. **Use the template**: Click [New Issue](../../issues/new/choose) and select the "Bug Report" template
3. **Be specific**: Provide detailed information including:
   - Clear description of the bug
   - Steps to reproduce
   - Expected vs. actual behavior
   - Environment details (OS, browser, version, etc.)
   - Screenshots or logs if applicable
4. **One issue per bug**: Create separate issues for different bugs
5. **Add labels**: Apply appropriate labels to help categorize the issue

### Requesting Features

1. **Check existing requests**: Search [existing issues](../../issues?q=is%3Aissue+label%3Aenhancement) for similar feature requests
2. **Use the template**: Select the "Feature Request" template when creating a new issue
3. **Explain the "why"**: Clearly describe:
   - The problem you're trying to solve
   - Your proposed solution
   - Benefits of implementing the feature
   - Any alternatives you've considered
4. **Be realistic**: Consider the scope and feasibility of your request

### Participating in Discussions

- **Be constructive**: Provide helpful feedback and suggestions
- **Stay on topic**: Keep discussions focused on the issue at hand
- **Be respectful**: Follow our [Code of Conduct](CODE_OF_CONDUCT.md)
- **Add value**: Share relevant information, workarounds, or insights

## 🏷️ Issue Labels

We use labels to organize and prioritize issues:

### Type Labels
- `bug`: Something isn't working correctly
- `enhancement`: New feature or improvement request
- `documentation`: Documentation improvements
- `question`: Further information is requested

### Status Labels
- `triage`: Needs initial review and categorization
- `confirmed`: Bug has been verified
- `in-progress`: Being actively worked on
- `blocked`: Cannot proceed due to dependencies
- `wontfix`: Will not be addressed
- `duplicate`: Duplicate of existing issue

### Priority Labels
- `priority-critical`: Urgent, requires immediate attention
- `priority-high`: Important, should be addressed soon
- `priority-medium`: Moderate importance
- `priority-low`: Nice to have

## ✅ Issue Quality Guidelines

Good issues have:
- **Clear titles**: Concise and descriptive (e.g., "Login button not working on mobile Safari")
- **Complete information**: All template fields filled out
- **Reproducible steps**: Others can recreate the issue
- **Context**: Relevant environment and configuration details
- **Evidence**: Screenshots, logs, or error messages when applicable

## 🚫 What Not to Report Here

This repository is for issue tracking only. Please don't use it for:
- Code contributions (there's no code in this repo)
- Support requests (use discussions instead)
- Spam or off-topic content
- Personal information or sensitive data

## 📞 Getting Help

- **General questions**: Use [GitHub Discussions](../../discussions)
- **Bug reports**: Use the bug report template
- **Feature requests**: Use the feature request template
- **Security issues**: Report privately through [Security Advisories](../../security/advisories/new)

## 🔄 Issue Lifecycle

1. **Created**: New issue is submitted
2. **Triaged**: Maintainers review and categorize
3. **Confirmed**: Issue is validated and accepted
4. **In Progress**: Work has begun (tracked in relevant code repositories)
5. **Resolved**: Fix is implemented and deployed
6. **Closed**: Issue is resolved or declined

## 📋 Best Practices

- **Update your issues**: If you discover new information, add it to your issue
- **Respond promptly**: Answer clarifying questions from maintainers
- **Test fixes**: Verify that fixes work when they're deployed
- **Close resolved issues**: If your issue is fixed, confirm and close it
- **Be patient**: Maintainers are often volunteers with limited time

## 🙏 Thank You

Your contributions help make SaveWorldOne better for everyone. We appreciate your time and effort in reporting issues and participating in discussions!

## 📜 Code of Conduct

This project adheres to a Code of Conduct. By participating, you are expected to uphold this code. Please report unacceptable behavior to the project maintainers.
